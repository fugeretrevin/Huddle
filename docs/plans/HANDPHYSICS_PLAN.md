# Hand ↔ Object Physics Plan (ISDK / Meta XR SDK v209, Quest 3 hand tracking)

Research + implementation plan. **Nothing here is implemented.** Scope: make grab/hold/release
feel stable and premium, keep props pushable when *not* held, keep hands colliding with the world,
and un‑park the dynamic finger‑wrap. Grounded in the actual project files.

## Project state this plan builds on (exact files)
- `Assets/MuseDesk/Scripts/Workspace/GrabbableRigidbody.cs` — polls `Grabbable.SelectingPointsCount`
  by reflection; **on grab** sets `_rb.isKinematic = true`; **on release** sets `isKinematic = false`
  and zeroes `linearVelocity`/`angularVelocity`. No collision‑layer handling.
- `Assets/MuseDesk/Scripts/Workspace/DynamicFingerCollision.cs` — `[DefaultExecutionOrder(2000)]`,
  overrides HandVisual joint rotations in **`LateUpdate`** by SphereCast against `grabbableMask`.
  `GloballyEnabled = false` (parked). Resolves `Oculus.Interaction.HandVisual` +
  `GetTransformByHandJointId(HandJointId)` by reflection; already has unused scaffolding for an
  event hook (`_usedEvent`, `HandRig.handler`).
- `Assets/MuseDesk/Scripts/Workspace/DelayedPhysics.cs` — keeps a prop kinematic `delay` seconds
  after load (follow‑then‑lock settle), then dynamic. Has `ResetToHome()`.
- `AgentScripts/HandPush.cs` (builder) — adds `HandPhysicsCapsules` as child `HandPhysicsPush` under
  `OVRHandVisualLeft`/`Right`, sets `_handVisual`, `_hand`, `_jointsRadiusFeature`, `_asTriggers=false`
  (solid), `_mask`=all. **Never assigns a layer to the capsules.** Also builds `PhysicsTray` props
  (`Prop_Block` mass 0.14, `Prop_Mug` mass 0.20; both `ContinuousDynamic`, damping 0.1/0.6, `DelayedPhysics`).
- `ProjectSettings/TagManager.asset` — only **one** custom layer: **`FingerCollide` = layer 8**.
  No `HandCapsule` or `Held` layer yet.

---

## (a) Root cause of each defect

### Defect 1 — PROP FLING
Confirmed by Meta's held‑object guidance + our setup: a **kinematic** held body does **not** respond to
collisions, so the prop is *not* flung *while held*. The fling happens in the two windows where the prop is
**dynamic and the solid capsules overlap it**:
1. **Approach (pre‑grab):** the solid capsules (`_asTriggers=false`) hit a dynamic prop as the hand
   closes. Some push is *wanted*; the *explosive* push comes from deep single‑step penetration at high
   hand speed → large separating impulse.
2. **Release:** `GrabbableRigidbody` flips `isKinematic=false` the instant selection drops. The capsules
   are usually still interpenetrating the prop at that frame, so PhysX resolves the overlap on the next
   step with a big impulse → the prop shoots out. Zeroing velocity (already done) doesn't help because the
   impulse is generated by the *penetration*, not by carried velocity.

The capsules are all on the **hands' default layer** (HandPush sets no layer), so there is no collision‑matrix
lever to separate "held prop" from "hand capsule" today.

### Defect 2 — DYNAMIC FINGER COLLISION "snaps back"
`DynamicFingerCollision` writes joint rotations in `LateUpdate` at execution order 2000, betting it runs
*after* ISDK. But `HandVisual.UpdateSkeleton()` (ISDK's joint writer) runs inside ISDK's own update and its
ordering vs. our `LateUpdate` is **not guaranteed** — when ISDK writes after us, our wrap is overwritten
every frame → flicker/"snap back". The API gives a precise hook: **`HandVisual.WhenHandVisualUpdated`** is an
`Action` raised *at the end of that HandVisual's update, after joints are written*. Writing in that callback
is last‑writer‑wins per hand, per frame.

## (b) Prop‑fling fix — collision‑layer / ignore strategy (the highest‑leverage change)

**Approach: two new layers + collision matrix + layer toggle on grab.** Cleaner than per‑collider
`Physics.IgnoreCollision` because it's matrix‑level and survives pooling/re‑parenting.

1. **Add layers** to `ProjectSettings/TagManager.asset` (pick free slots, e.g. 9 = `HandCapsule`,
   10 = `Held`). Editable via `SerializedObject(AssetDatabase.LoadAllAssetsAtPath("ProjectSettings/TagManager.asset")[0])`
   → `layers` array, or by hand.
2. **Collision matrix** (`Physics.IgnoreLayerCollision`): `Held` × `HandCapsule` = **ignored**.
   Leave `Held` × Default/desk = **on** (held/just‑released prop still rests on the desk). Set this once at
   startup in a tiny bootstrap (`Physics.IgnoreLayerCollision(Held, HandCapsule, true)`) so it's robust even
   if the saved matrix drifts.
3. **Put the capsules on `HandCapsule`.** The capsule colliders are generated at **runtime** by
   `HandPhysicsCapsules` as children of `HandPhysicsPush`, so an edit‑time layer set won't catch them. Add a
   small runtime component `HandCapsuleLayer` on each `HandPhysicsPush` that, for the first ~30 frames and
   whenever `childCount` changes, sets every descendant collider's `gameObject.layer = HandCapsule`. Cheap,
   idempotent.
4. **Toggle the held prop onto `Held`.** In `GrabbableRigidbody`:
   - **On grab:** record each collider's original layer, set the prop (and collider children) to `Held`.
     Keep the existing `isKinematic = true`.
   - **On release:** keep it on `Held` for `releaseIgnoreSeconds` (≈0.30 s) *after* going dynamic, so the
     capsules can't impulse the body while they're still overlapping; then restore the original layer so the
     prop is pushable again. Keep the existing zero‑velocity.
   - Net: held + just‑released prop is invisible to the capsules (no squeeze, no release‑kick); everything
     else unchanged.
5. **Tame approach push** (prop *not* held, still collides with capsules): keep `ContinuousDynamic`; add
   `Rigidbody.interpolation = Interpolate`; modestly raise `linearDamping` and mass if pushes still feel
   explosive. This keeps "pushable" while killing the spike.

**Alternative (no new layers):** enumerate the runtime capsule colliders under `HandPhysicsPush` and call
`Physics.IgnoreCollision(propCol, capsuleCol, true)` on grab / `false` after the release window. Works, but
you must re‑enumerate as capsules regenerate — more fragile than the layer matrix. Prefer layers.

## (c) Dynamic finger collision — correct update hook

Replace the `LateUpdate` + `[DefaultExecutionOrder(2000)]` with a **subscription to
`HandVisual.WhenHandVisualUpdated`** (confirmed `Action`, no args) per rendered hand:

- Resolve the event by reflection: `evt = hvType.GetEvent("WhenHandVisualUpdated")`.
- For each `HandRig`, build a parameterless closure `Action h = () => SolveHand(rig);` and
  `evt.AddEventHandler(rig.handVisual, h)`; store `h` on the rig to `RemoveEventHandler` in `OnDisable`.
- Move the body of `LateUpdate` into `SolveHand` called from that callback. Delete the execution‑order
  attribute. Keep `GloballyEnabled` as the master switch; keep the proximity gate + `grabbableMask` so it
  only wraps near a grabbable and never clamps on the desk.
- Joint access is unchanged (`GetTransformByHandJointId`); `HandVisual.Joints` (`IList<Transform>`, index by
  `(int)HandJointId`) is an equivalent fallback. `GetJointPose(jointId, Space)` is available if you need poses.
- **Do not** call `UpdateSkeleton()` (docs: "should not be called directly"). **Do not** use `SyntheticHand`
  for this — that edits the *data chain* and would fight the grab transformer; we want **visual‑only** wrap,
  which is exactly what driving the HandVisual transforms in the post‑update event gives.

Keep `smoothing` (the `lastWorld` slerp) to avoid jitter now that writes land every frame cleanly.

## (d) HandPhysicsCapsules recommended config
- Keep `_asTriggers = false` (solid) so hands push world props — this is the desired feel.
- Keep `_handVisual` / `_hand` / `_jointsRadiusFeature` wired from the **modified** HandVisual (as HandPush
  does) — Meta warns the raw `OVRSkeleton` "Enable Physics Capsules" path uses unmodified data and mismatches.
- **New:** route the generated capsules onto the `HandCapsule` layer (step b‑3) so the matrix can exclude held
  props.
- Narrow `_mask` to the layers hands should physically hit (desk/props), not UI/agents, to cut cost and avoid
  nudging agents/cards. (Currently all.)

## (e) "Grab haptics" — corrected assumption → audio/visual pseudo‑haptics
**Bare hand tracking has no haptic actuator** (no controller in the hand), so controller haptics
(`OVRInput.SetControllerVibration`, or the standalone Meta Haptics SDK `Oculus.Haptics.HapticClipPlayer`)
**do nothing in hand‑tracking mode.** Deliver "feel" another way, on the grab event:
- **Audio:** fire a short pluck/“tock” on select and a soft set‑down on unselect via the existing
  `FeedbackController` procedural tones. Hook ISDK's grab event, not a poll: the `Grabbable` /
  `PointableElement` raises `WhenPointerEventRaised(PointerEvent)` with `PointerEventType.Select` /
  `Unselect`; or reuse the card/paper pattern via `InteractableUnityEventWrapper`.
- **Visual:** a 1‑frame scale‑pop / rim‑highlight on the grabbed object (and a subtle hand‑tint) sells
  contact. Cheapest convincing "haptic" in passthrough.
- Keep controller haptics behind a `usingControllers` check for the (unlikely) controller path.

## (f) Implementation checklist (a builder script can follow)
1. `TagManager.asset`: add layers `HandCapsule` (9) and `Held` (10).
2. Startup bootstrap (one component on `AppServices`): `Physics.IgnoreLayerCollision(Held, HandCapsule, true)`;
   optionally also set the matrix asset so it persists.
3. New runtime `HandCapsuleLayer` on both `HandPhysicsPush` GOs → set generated capsule descendants to
   `HandCapsule` (first ~30 frames + on `childCount` change). Update `HandPush.cs` to add it + narrow `_mask`.
4. Edit `GrabbableRigidbody.cs`: cache collider layers; on grab → `Held`; on release → stay `Held`
   `releaseIgnoreSeconds` (0.30 s), then restore; add `interpolation = Interpolate`. Keep kinematic/zero‑vel.
5. Edit `DynamicFingerCollision.cs`: subscribe `WhenHandVisualUpdated`, move solve into the callback, drop
   the execution‑order hack, unsubscribe in `OnDisable`. Flip `GloballyEnabled = true` only after step 7.
6. New grab‑feedback hook: SFX+visual pop on select/unselect via the ISDK pointer event.
7. Rebuild APK, install, verify on‑head; tune `releaseIgnoreSeconds`, damping, `boneRadius`, `proximityGate`.

## (g) Verification (Editor Play Mode stalls without an HMD)
- **In‑editor (safe):** compiles; layers exist; `Physics.GetIgnoreLayerCollision(Held,HandCapsule)==true`;
  `GrabbableRigidbody` layer‑swap logic via an isolated eval that calls the grab/release transitions directly
  and asserts `gameObject.layer`; that `WhenHandVisualUpdated` resolves + handler count > 0 (reflection eval);
  Scene‑View capture for prop/tray placement only.
- **Must be on‑head (adb logcat):** fling gone on approach/pinch/release; props still pushable unheld; hands
  still hit the desk; fingers wrap (tag `MDFINGER`), grab still fires (tag `MDGRAB`), SFX/visual on grab; FPS.
  Use `adb -s 2G97C5ZHCK037K logcat` filtered to `MDFINGER`/`MDGRAB`. Add a one‑line `MDFINGER subscribed
  via event (hands=N)` log at Start so the hook is confirmable from logcat without an HMD view.

## (h) Risks / rollback
- Every change is flag‑/layer‑gated and reversible. `DynamicFingerCollision.GloballyEnabled=false` instantly
  reverts to clean ISDK hands. `GrabbableRigidbody` layer swap: if mis‑tuned, remove the `Held` assignment and
  it behaves exactly as today.
- **Layer‑index collisions:** confirm 9/10 are free before writing `TagManager`; a wrong index silently breaks
  the matrix. Assert the layer *names* resolve at startup.
- `_mask` narrowing could stop a wanted interaction — verify hands still push tray props after narrowing.
- Subscribing the event on hands that are recreated/toggled (ISDK rebuilds visuals): re‑resolve rigs on
  enable, and guard against double‑subscription (store/remove the delegate).
- Capsule‑layer runtime setter must not fight ISDK if ISDK re‑parents capsules — keep it idempotent and cheap.

---

## Top 3–5 highest‑leverage changes
1. **`Held` × `HandCapsule` collision‑matrix exclusion + layer toggle in `GrabbableRigidbody`** — kills
   grab/pinch/release fling directly while keeping unheld props pushable. Biggest feel win.
2. **Route runtime capsules onto a `HandCapsule` layer** (`HandCapsuleLayer` component) — the enabler for #1
   and lets you narrow what hands collide with.
3. **Switch `DynamicFingerCollision` to the `WhenHandVisualUpdated` event** — un‑parks finger‑wrap; the
   hypothesis was correct, and the API confirms it's a plain `Action` fired post‑joint‑write.
4. **Grab audio/visual pseudo‑haptics on the ISDK pointer event** — cheap premium‑feel upgrade that actually
   works in hand tracking (controller haptics do not).
5. **Release‑window + interpolation tuning** — `releaseIgnoreSeconds` ≈0.30 s + `Interpolate` removes the
   residual settle‑kick.

## Where ISDK differed from our assumptions
- **Haptics:** our "grab haptics" assumption doesn't apply to bare hands — no actuator. Reframed to
  audio/visual. (The Haptics SDK `HapticClipPlayer` is a separate package and controller‑only.)
- **`WhenHandVisualUpdated`:** confirmed to exist and be a plain `Action` (not `Action<HandVisual>`); the
  parked LateUpdate hypothesis was right in spirit — the event is the clean, ordering‑safe version.
- **No capsule layer field was ever set** in our build, so there's no existing lever — the layer work is net‑new
  but small.
- Meta docs don't publish an official "exclude held object from hand capsules" recipe; the layer‑matrix
  approach here is the community‑standard equivalent, adapted to ISDK.
